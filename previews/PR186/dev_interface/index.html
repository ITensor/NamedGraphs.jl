Developer Interface

This page describes how to define a new AbstractNamedGraph: subtype it and overload the minimal interface below, the graph on integer vertex codes and the translation between names and codes. Everything else in the Graphs.jl interface has generic fallbacks in terms of these. Graph types that do not store an integer graph get a generic EncodedGraphView fallback for encoded_graph and only need encode_vertex and decode_vertex.

Vertex codes are not stable across mutation: adding or removing vertices may reassign the codes of other vertices.

NamedGraphs.AbstractNamedGraph — Type
AbstractNamedGraph{V} <: Graphs.AbstractGraph{V}

Abstract type for graphs whose vertices are names of type V rather than contiguous integers. Subtypes implement the Graphs.jl interface in terms of a graph on integer vertex codes through the minimal interface encoded_graph, encode_vertex, and decode_vertex.

source
NamedGraphs.encoded_graph — Function
encoded_graph(graph::AbstractNamedGraph) -> AbstractGraph{Int}

The graph in coded form: a graph with the same topology as graph whose vertices are the codes 1:nv(graph) of the vertices of graph, i.e. it has the edge encode_vertex(graph, u) => encode_vertex(graph, v) if and only if graph has the edge u => v.

May be a stored field or a view of graph; mutate the graph only through graph.

source
NamedGraphs.encode_vertex — Function
encode_vertex(graph::AbstractNamedGraph, vertex) -> Int

The code of vertex in graph, i.e. the corresponding vertex of encoded_graph(graph). encode_vertex(graph, ·) and decode_vertex(graph, ·) are inverse bijections between vertices(graph) and Base.OneTo(nv(graph)).

Codes are not stable across mutation: adding or removing vertices may reassign the codes of other vertices.

source
NamedGraphs.decode_vertex — Function
decode_vertex(graph::AbstractNamedGraph, code::Integer)

The vertex of graph whose code is code, i.e. the vertex corresponding to the vertex code of encoded_graph(graph). Inverse of encode_vertex.

source
NamedGraphs.encode_edge — Function
encode_edge(graph::AbstractNamedGraph, edge) -> AbstractEdge{Int}

The edge of encoded_graph(graph) corresponding to edge, i.e. the edge between the codes of the vertices of edge. Inverse of decode_edge.

source
NamedGraphs.decode_edge — Function
decode_edge(graph::AbstractNamedGraph, encoded_edge)

The edge of graph corresponding to the edge encoded_edge of encoded_graph(graph). Inverse of encode_edge.

source
Graphs.vertices — Method
vertices(graph::AbstractNamedGraph) -> AbstractIndices

The set of vertices of graph: an AbstractIndices containing each vertex exactly once, with fast membership testing.

The vertices iterate in insertion order: they appear in the order they were added to the graph, removing a vertex does not reorder the rest, and added vertices appear at the end. The iteration order therefore does not in general match the vertex codes after removals, since codes are reassigned. Use decode_vertex for the vertices in code order, for example map(c -> decode_vertex(graph, c), 1:nv(graph)).

The output is a live read-only view of the graph: do not mutate it directly, and do not rely on it (or containers sharing its state) across mutations of the graph.

source
Graphs.edges — Method
edges(graph::AbstractNamedGraph) -> AbstractEdgeIter

An iterator over the edges of graph, yielding each edge exactly once, with membership testing (in) matching has_edge (in particular, on undirected graphs an edge and its reverse are both members while iteration yields each edge once). The iteration order is unspecified.

The output is a live view of the graph: do not rely on it across mutations of the graph.
